11 . BDD SQL

Conditions d’achèvement
1.1 | Passage à l'échelle
7 h ⚙ autonomie
Travail individuel en autonomie
⚙ Temps en autonomie — L'apprenant travaille seul sur les notions et les exercices ci-dessous, à son rythme.
🎯 Objectif

Comprendre le rôle des indexes et des types de données dans les performances SQL, et savoir analyser et optimiser une base pour le passage à l'échelle.

Contextes possibles d'une application dont le passage à l'échelle est délicat
  • L'application existe quand vous arrivez en tant que développeur, elle a des années d'historique et de données. Elle gère un large volume de données client. Le DBA va kill toute requête qui lock la base ne serait-ce que quelques secondes.
  • Application from scratch mais big data. Maîtrise des coûts du cloud pour une entreprise jeune, impossible de mettre dans des clouds publics avec des solutions big data, trop cher.
Déroulement
1
 Connaissances — Indexes 30 min — Les performances sont permises par les indexes. Ces derniers doivent être présent sur les colonnes des clause WHERE, JOIN, HAVING, clés étrangères et primaires. Là où on cherche.
Le SGDB et la RAM qu'il utilise doit être paramétré pour que les indexes soient en RAM pour une haute vitesse d'accès (par rapport au disque).
Qualité de l'indexe par rapport à la cardinalité de la colonne. Indexer un bouléan est peu utile.
Indexes composites pour les WHERE … AND.
Pas d'indexes inutiles, il prennent de la place en RAM/disque.
  • planetscale.com — Introduction to indexes
2
 Connaissances — Types 30 min — Choisir les types de la plus petites taille (en bytes) possible. Exemple d'un type numérique, une colonne de prix en € de biens immobiliers, MEDIUMINT suffit, cf dev.mysql.com — Integer types. Surtout pour les colonnes qui sont indexées.
  • dbdesigner.net — Choosing the right database data types for performance and accuracy
3
 Connaissances — Analyse des requêtes 30 min — EXPLAIN ANALYZE <requête SQL>. Comparer tous les types de résultats de ces instructions quand on a pas d'indexe pour la requête, un mauvais indexe, un indexe sub-optimal et le parfait indexe.
4
 Exercice 1  3 h — Créer une base avec les unités légales actives et établissements actifs du répertoire de la base SIRENE. Le backend affiche un formulaire qui permet la recherche par numéro SIREN, numéro SIRET, code postal, département et le code activité de l'entreprise. L'apprenant doit ajouter uniquement les indexes manquants et utiles.
5
 Exercice 2 30 min — Fournir un script qui liste les entreprises (pas les établissements) ouvertes dans le 74. L'apprenant doit rajouter l'indexe manquant le plus performant possible pour ce script et vérifier son usage.
6
 Exercice 3 30 min — Fournir une base de données volumineuse et son backend. L'application est performante grâce aux indexes mais trop de données, il faut trouver les indexes inutiles et les supprimer pour réduite la taille de la base.
7
 Exercice 4 30 min — Toujours sur la même base, certains type ne sont pas les plus petits possible, l'étudiant doit trouver lesquels grâce à des requêtes SQL et les optimiser.
  • data.gouv.fr — Jeu de données de la base SIRENE
8

Exercice bonus:

  1. Enregistrer la taille de la base, données et indexes.
  2. Ajouter à chaque unité légale la dénomination quand elle est disponible.
  3. Enregistrer la taille de la base, données et indexes.
  4. Configurer le serveur MySQL pour les caractères français.
  5. Mesurer le temps d'un SELECT sur une dénomination.
  6. Ajouter un indexe de type FULLTEXT sur ce champs.
  7. C'est quoi un indexe FULLTEXT ?
  8. Enregistrer la taille de la base, données et indexes.
  9. Mesurer le temps d'un MATCH sur une dénomination.
  10. Analyser ces résultats.
📦 Livrables
  • Base SIRENE (Unité Légale et Établissement) avec les indexes manquants et utiles ajoutés (Exercice 1)
  • Script listant les entreprises créées dans le 74 en 2025, avec l'indexe manquant ajouté (Exercice 2)
  • Base allégée après suppression des indexes inutiles (Exercice 3)
  • Liste des types de colonnes optimisés avec les requêtes SQL utilisées pour les identifier (Exercice 4)

📚 Notions acquises
  • Indexes (WHERE, JOIN, HAVING, clés étrangères/primaires)
  • Cardinalité et qualité d'un indexe
  • Indexes composites
  • Types de données SQL et leur taille en bytes
  • EXPLAIN ANALYZE
🎯 Compétences
  • Ajouter les indexes manquants et utiles à une base de données
  • Identifier et supprimer les indexes inutiles pour réduire la taille d'une base
  • Optimiser les types de colonnes grâce à des requêtes SQL
  • Analyser les performances d'une requête avec EXPLAIN ANALYZE
