11 . BDD SQL

Conditions d’achèvement
🎯 Objectif

Découverte du paradigme NoSQL pour les bases de données.

Vous allez découvrir et mettre en œuvre des requêtes sur des bases de données non relationnelles, afin d'en découvrir certains concepts, avantages et limites.

Partie 0
Découverte du NoSQL — 1h
0.1 | Découverte du monde du NoSQL
⚙ autonomie
Déroulement

Les bases de données NoSQL (Not only SQL) ont été conçues pour faire ce que SQL avait des difficultés à faire. En particulier, SQL a des difficultés pour gérer des données non-structurées/semi-structurées dans des volumétries assez grandes. C'est sur ce segment que les solutions NoSQL se sont développées.

Avant de se lancer dans la manipulation et la création de requêtes sur ce type de bases, il est important de noter qu'une base de données ne peut pas être à la fois tolérante au partitionnement, cohérente et disponible, ce phénomène s'appelle le CAP théorème.

1
 Que signifie NoSQL ?
2
 Renseignez vous sur le CAP théorème, où se situent les différentes bases de données que vous connaissez ?
3
 Écrivez un mémo sur le CAP théorème dans lequel vous situerez les bases de données non-relationnelles présentes dans les ressources que vous parcourez.

    0.2 | Installation de l'environnement de travail
    ⚙ autonomie
    Déroulement
    1
    		 Dans un nouveau dossier, téléchargez le fichier docker-compose.yml donné en ressources ; placez-le dans un nouveau dossier.
    2
    		 Démarrer la stack proposée dans le fichier docker compose à l'aide du service docker installé au début du module. (commande docker compose up depuis le nouveau dossier créé)
    3
    		 Comme vous l'avez peut être déjà remarqué, la stack contient 2 services, mongodb et neo4j, ces deux services correspondent aux deux bases de données que nous allons utiliser dans la suite du module !
    4
    		 Les différentes bases de données proposent souvent des outils simplifiant leurs utilisations (comme le fameux phpmyadmin ou pgadmin connu des utilisateurs de mysql/postgresql ...). Dans le cas de mongodb deux possibilités s'offrent à vous :
    • Si vous vous sentez à l'aise lors de la manipulation de la ligne de commande, installez mongosh
    • Sinon installez mongodb-compass (recommandé) cet utilitaire contient aussi un shell mongosh, il simplifie la connexion et donne une vue d'ensemble de la base.
    5
    		 Pour Neo4j, un utilitaire web est proposé, la méthode pour s'y connecter sera présentée en temps voulu.

    Partie 1
    Les bases de données orientées documents — 3h

    Cette partie est consacrée au gestionnaire de base de données orientés documents mongodb, vous remarquerez que les requêtes ressemblent à du code JavaScript. Le serveur MongoDB a son propre moteur JavaScript basé sur SpiderMonkey de Mozilla (cf. https://www.mongodb.com/docs/manual/core/server-side-javascript/#unsupported-array-and-string-functions).

    1.1 | Connection à MongoDB
    ⚙ autonomie
    Déroulement

    Mongodb stocke les données sous forme de documents dans des collections, pour voir plus clairement à quoi correspondent les documents et collections, effectuez les étapes suivantes.

    1
    		 Utilisez mongodb-compass pour vous connecter à votre base de donnée mongodb démarrée en utilisant docker dans l'itération précédente. La base de données se trouve sur l'ip 127.0.0.1 sur le port 27017.
    2
    		 Une fois connecté, constatez que vous avez 3 databases nommées admin, local et config.
    3
    		 Dans le shell mongosh :
    • Sélectionnez la base nommée "admin"
    • Affichez les collections contenues dans la base
    • Affichez tous les documents contenus dans la collection nommée "system.version"
    Qu'est-ce qu'une collection ? Comment est représenté un document ?

    1.3 | Quelques recherches sur les films
    ⚙ autonomie
    Déroulement

    Une recherche dans mongodb utilise la méthode find et se décompose en trois parties, la requête, la projection à adopter et des options : find( {requête}, {projection}, {options}). À quoi correspond une projection ?

    1
    		 Maintenant, comme l'a fait George Orwell, intéressons nous à l'année 1984 :
    1. Quelle requête permet d'afficher tous les films réalisés en 1984 ?
    2. Utilisez une opération d'aggrégations pour afficher le nombre de films réalisés cette année-là.
    3. Concevez une requête permettant d'afficher 5 titres de films réalisés en 1984
    4. En considérant qu'un bon film a une note (rating) supérieure à 7 chez "imdb" :
      1. Combien y a t'il eu de bon films en 1984 ?
      2. Quels sont les titres des 5 meilleurs films de 1984 ?
    5. Vous connaissez sûrement Steven Spielberg :
      1. Combien de films a-t'il dirigé en 1984 ?
      2. Quels sont leurs notes (rating) et leurs titres et leurs plots ?
    6. Dans combien de films a joué Charles Dance ?
    7. Quelle est l'année du film le plus ancien ? Celle de celui le plus récent ? Quelles années n'ont pas de films ?
    8. Quelle est l'année pendant laquelle le plus de films ont été réalisés ?

    2.2 | Un Premier Graphe, Parlons de Pizza
    ⚙ autonomie
    Déroulement

    Les graphes sont des structures de données composées de nœuds et d'arêtes liant ces nœuds entre eux. Dans Neo4J, ce type de données sera manipulé. Pour cela Neo4J fournit un langage, Cypher, qui va être utilisé pour la suite de cette partie. Ce type de langage s'appelle un Graph Query Language, renseignez vous rapidement sur ce type de langage.

    1
    		 Maintenant, créons des pizzas à l'aide de cypher :
    1. Créez un noeud de type ":Pizza" ayant un attribut "name" avec pour valeur "Margherita"
    2. Créez un second noeud de type ":Pizza", ce noeud aura "Royale" comme attribut "name"
    3. Effectuez une requêtes pour voir tous les noeuds de type ":Pizza"
    2
    		 Félicitations, vous avez fait votre premier graphe ! Mais... ce graphe ne contient pas d'arêtes, allons ajouter du fromage sur les deux pizzas.
    1. Créez un nouveau noeud de type ":Cheese" avec comme nom "Mozzarella"
    2. Liez ce noeud aux deux pizzas
    3. Visualisez le graphe
    4. Ajoutez un ingrédient qui sera seulement sur la pizza royale
    5. Visualisez votre graphe
    3
    		 Maintenant que vous savez créez des pizzas, mangeons les !
    1. Utilisez les primitives de Cypher pour supprimer les nœuds et les arêtes créés précédemment

    2.4 | Revenons à nos films ; Ça tourne !
    ⚙ autonomie
    Déroulement

    Commençons par regarder à quoi ressemble le graphe chargé.

    1
    		 Créez une requête pour afficher tous les nœuds et leurs relations.
    2
    		 Entrons maintenant à l'aube des années 2000, et vous commencez à créer des requêtes pour répondre aux questions suivantes :
    1. Afficher tous les films sortis en 1999.
      1. Combien y en a t'il ?
      2. À l'aide d'une requête, vérifiez qu'il existe un film nommé : "The Matrix", sorti en 1999.
    2. Entrons maintenant dans la matrice, quels sont les personnes en lien avec le film "The Matrix" de 1999.
      1. Affichez maintenant les personnes ayant joué dans ce film.
      2. Comptez les.
    3. Combien d'acteurs ont joué dans au moins un film contenant Matrix dans son titre ?
    4. Comment s'appelle l'acteur le plus jeune ayant joué dans un de ces films ?
      1. Dans quels autres films a joué cet acteur ?
      2. Quel a été le premier film dans lequel il a joué ?
    5. Combien d'acteurs ont joué dans tous les films contenant "Matrix" dans leurs titres ?
    6. Trouvez les acteurs ayant seulement joué dans le film Unforgiven
      1. Combien y a t'il de films avec un lien de type "ACTED_IN" ou "DIRECTED" entre Clint Eastwood et Lilly Wachowski.
